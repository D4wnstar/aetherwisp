**Distributed memory** is a concept in compute cluster architecture where each process in the cluster (usually equivalent to a thread, and thus a core) only has direct access to the local memory of the CPU it's running on. For a CPU to access the memory of a different node, it must use **message passing**, meaning it must send a message to a node requesting access to that memory. It is opposed to **shared memory**, where all CPUs have access to all memory, through **bus interconnects**.

The value of distributed memory is that it natively scales with the number of processors; since each processor has its own memory, adding more processors simply increases memory proportionally. However, it is more difficult to reason about due to fragmented address spaces (each CPU has its own isolated memory) and it leaves the complexity (and correctness!) of data communication to the programmer. Finally, it leads to highly non-uniform memory access times as they now depend on the physical distance between nodes.

Both shared and distributed memory access paradigms are in use. In fact, a distributed system is just a cluster of individual machines, each of which is a shared memory system. Shared memory architectures require custom compilers, but once that's accessible, the source code is easily portable. Furthermore, shared memory programs only need a simple UNIX shell to be executed. On the other hand, distributed computing uses regular compilers, but depends on external libraries, which makes portability more difficult, and a specific runner that isn't a simple UNIX shell. The standard for shared computation is **[[OpenMP]]**, while the standard for distributed computing is **[[Message Passing Interface|MPI]]**. The two paradigms can even be mixed by using OpenMP and MPI in the same software.
