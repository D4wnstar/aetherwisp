The **naive Bayes** [[Classification|classifier]] is a kind of classifier technique based on [[Bayes' theorem]].
### Formulation
Assume a classification problem with $p$ input categorical variables $X_{1},\ldots,X_{p}$ where $X_{j}=\{ x_{j,1},\ldots,x_{j,h_{j}} \}$ and $k$ output categories $Y=\{ y_{1},\ldots,y_{k} \}$. Invoking Bayes' theorem, we know that
$$P(\text{event}|\text{evidence})=P(\text{event}) \frac{P(\text{evidence}|\text{event})}{P(\text{evidence})}$$
In our case, the event is a specific class $y=y_{m}$ that we are trying to predict. The evidence is the observation $x=(x_{1,l_{1}},\ldots,x_{p,l_{p}})$ that we start with. Then
$$P(y=y_{m}|x_{1,l_{1}},\ldots,x_{p,l_{p}})=P(y_{m}) \frac{P(x_{1,l_{1}},\ldots,x_{p,l_{p}}|y_{m})}{P(x_{1,l_{1}},\ldots,x_{p,l_{p}})}$$
In order to run prediction with this equation, we just need to calculate this [[probability]] for each class $y_{1},\ldots,y_{k}$ and then pick the one with the highest probability (e.g. $\text{arg max}$ over all $m$). Notably, since we are merely trying to compare different probabilities, we do not need to compute $P(x_{1,l_{1}},\ldots,x_{p,l_{p}})$! This is because it is the same across all categories, so during comparison it cancels out. In practice, to use the **Bayes classifier** we only need the [[prior]] probability of the event $P(y_{m})$ and the [[likelihood]] of the observation given the event $P(x_{1,l_{1}},\ldots,x_{p,l_{p}}|y_{m})$.

So where do we find the prior and likelihood? We learn them by example through the training [[dataset]]! By seeing examples, we can infer correlations between observations and events that we can then reuse to predict future behavior. For $P(y_{m})$, we just count the number of observation with $y=y_{m}$. For $P(x_{1,l_{1}},\ldots,x_{p,l_{p}}|y_{m})$ we count the number of observations with $y=y_{m}$ *and* $x=(x_{1,l_{1}},\ldots,x_{p,l_{p}})$. This latter one however could come up as zero, which is not *that* unlikely, especially if your input variables are continuous. Moreover, there can be a very large number of different likelihoods given the sheer amount of possible combinations of $x$ and $y$: indeed there are $k\prod_{i=1}^{p}h_{i}$ possible likelihoods. To make this a little more manageable, we can introduce a new assumption: *the independent variables are independent from each other*. This apparently trivial statement is more complicated than it looks, because the two "independents" refer to different things. The first one means that observations $x_{i}$ are independent from the events $y$[^1]. The second means that observations $x_{i}$ are independent from *other* observations $x_{j\neq i}$. This is referred to as the **independency hypothesis** and with it, we have a **naive Bayes classifier**.

Assuming the independency hypothesis holds, we can simplify Bayes' theorem from[^2]
$$P(y_{m}|x_{1,l_{1}},\ldots,x_{p,l_{p}})=P(y_{m}) \frac{P(x_{1,l_{1}},\ldots,x_{p,l_{p}}|y_{m})}{P(x_{1,l_{1}},\ldots,x_{p,l_{p}})}=P(y_{m}) \frac{P(x_{1,l_{1}}|y_{m},\ldots,x_{p,l_{p}}|y_{m})}{P(x_{1,l_{1}},\ldots,x_{p,l_{p}})}$$
to
$$\boxed{P(y_{m}|x_{1,l_{1}},\ldots,x_{p,l_{p}})=P(y_{m}) \frac{P(x_{1,l_{1}}|y_{m})\ldots P(x_{p,l_{p}}|y_{m})}{P(x_{1,l_{1}},\ldots,x_{p,l_{p}})}}\tag{1}$$
We turned a complicated likelihood probability into $p$ much simpler "partial likelihoods". From a numerical standpoint, this produces $\sum_{i=1}^{p}kh_{i}$ combinations of "partial likelihoods" that are computed during learning.

The [[Artificial Intelligence/Machine learning/Model|model]] is hence nothing more than a simple collection of $k+\sum_{i=1}^{p}kh_{i}$ numbers: $k$ priors and $\sum_{i=1}^{p}kh_{i}$ partial likelihoods. That's all you need to run predictions, which as you may imagine is *very very* fast: just a few multiplications to calculate $(1)$. Speed is indeed the biggest boon of the naive Bayes classifier: while its performance can be shaky, it is so fast that it can be used on enormous datasets without issues. It's also easily explained: it's just a bunch of Bayes' theorem parameters, which we understand quite well. Unfortunately though, it suffers from a major issue: the independency hypothesis is *always false*. There will always *some* correlation between observations, so strictly speaking the naive Bayes classifier is always just an approximation, even with perfect unbiased data. How *good* of an approximation it is depends on how close to being true the independency hypothesis is, which depends greatly on the data you have and the nature of the phenomenon you are trying to explain. This is a domain-specific question that limits what you can (or rather, should) use naive Bayes with. Moreover, it's limited to classification; while there are extensions of naive Bayes for numerical *input*, the output is always a class. Some additional nice-to-haves are the lack of hyperparameters that require tuning and native support for missing values (just remove the missing partial likelihood from the product).

[^1]: Recall that "independent variables" is one of the several names for the input observations. It refers to the fact that inputs are raw data that's just "there" and is not calculated (i.e. dependent) from something else. It's the algebra sense of "independent" where $x$ is the independent piece of the equation $y=y(x)$. It does not refer to the [[independent variables|statistical sense]], which is what the second "independent" refers to.

[^2]: The equality $P(x_{1,l_{1}},\ldots,x_{p,l_{p}}|y_{m})=P(x_{1,l_{1}}|y_{m},\ldots,x_{p,l_{p}}|y_{m})$ is always true.
